Getting started

From OAI CU/DU Lab

Before launch

  1. Read current status.
  2. Obtain sole ownership of the core, CU, DU, routes, tunnels, radios, modem, and phone.
  3. Discover the physical location and UHD visibility of the required B210 on each selected radio host.
  4. Record the actual repository and external OAI commits.

Operator interface

./oai-lab --check-local-setup
./oai-lab
./oai-lab --help

Read-only checks

./oai-lab --status
./oai-lab --logs
./oai-lab --minipc-ethernet --verify
node scripts/tests/oai-lab-static.test.mjs

--verify, --status, and --logs contact configured hosts. --check-local-setup and the static suite do not.

Single entry point: always use ./oai-lab. Files under scripts/lib/ are internal and must not be launched directly.

Direct launch examples

./oai-lab --minipc-ethernet --start-ethernet
./oai-lab --pi-wifi-gre --start-wifi-gre
./oai-lab --jetson-quectel-wg --start-quectel-wg
./oai-lab --start-mono
Mutating actions: launch, PWS update, stop, and rollback require exclusive lab ownership. Use the interactive console to stop the current configuration and check the resulting state.

Evidence location

Run records are written outside the repository:

~/.local/state/oai-cu-du-lab/runs/

Set OAI_LAB_STATE_DIR to choose another private location.

Note: do not copy raw logs, packet captures, credentials, subscriber data, or generated configurations into Git.
