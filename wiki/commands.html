Operator TUI Interface

The lab is primarily controlled using a custom interactive command-line TUI utility written in Node.js. It simplifies process stop/start coordination, configuration generation, and validation checks.

Usage Recommendation

Always run TUI actions from the root directory of the repository. This guarantees paths, configuration files, and scripts are resolved correctly.

./scripts/oai-lab-tui

Automated CLI Switches

For non-interactive runs, continuous integration, or automation, you can run the TUI with the following direct command line flags:

Flag Operation Description
--verify Run preflight SSH and hardware checks for Firecell and active DU target.
--start-mono Stop other scenarios and start monolithic core & gNB on serber-firecell.
--start-ethernet Stop monolithic core, run split core on Firecell, add stale DU isolation rules, and start Ethernet CU/DU.
--start-caged-quectel Legacy experimental launcher. It does not yet implement the target one-CU, donor-DU, and access-DU topology and must not be used as proof of that architecture.
--validate-caged-quectel Refresh routes/tunneling and re-evaluate packet flows for the running Quectel backhaul.
--rollback-caged-quectel Stop Quectel backhaul processes and clean up WireGuard/routes.
--experimental-b210 Probes UHD USRP B210 channel capability and isolates interfaces.

Performance Metrics & Data Collection

To measure the system's performance under load, use the split performance window script. It monitors process status, interface traffic levels, and schedules metrics collection without interrupting active gNB/CU/DU processes.

./scripts/collect-split-performance-window.sh [duration-seconds]
Performance Measurement Tip

Start a sustained downlink traffic transfer (e.g., using iPerf3 or downloading a test file on the Nothing Phone) before running the performance collector. The default collection window is 60 seconds.

Generated Evidence Outputs

Upon completion, the collector outputs a timestamped folder under experiments/YYYYMMDD_HHMMSS_split_performance_window/ containing:

  • logs/cu-filtered.log & logs/du-filtered.log: Log lines containing milestones, F1, SCTP, and BLER events.
  • measurements/minipc-to-firecell-ping.txt: RTT latency between CU and DU hosts.
  • measurements/du-scheduler-summary.txt: Derived summary of downlink scheduling rounds, average MCS range, block error rates, and LCID 4 byte counts.
  • logs/core-filtered.log: Docker container logs filtered for registration, context, SMF Warnings, and session changes.

Manual OAI Commands (Under the Hood)

For debugging, operators may need to inspect processes, logs, and containers manually on the host machines.

Process Management

The gNB softmodem runs as a native Linux binary nr-softmodem. Check its active process state, thread mappings, and CLI args:

pgrep -a nr-softmodem

Active Logs Inspection

Both CU and DU output runtime logs directly to the local /tmp directory of their respective host machines:

  • CU host (Firecell): tail -f /tmp/oai-cu-ethernet.log
  • DU host (Minipc): tail -f /tmp/oai-du-ethernet.log

Docker Core Containers

The 5G Core Network (5GC) runs inside Docker containers on serber-firecell. Check the status of these containers:

docker ps --filter "name=oai-cn5g"

View active AMF and SMF logs for UE registration issues:

docker logs oai-cn5g-minipc-oai-amf-1 --tail 100 -f
docker logs oai-cn5g-minipc-oai-smf-1 --tail 100 -f

Network & Diagnostics

Use these commands on the hosts to verify routes, sockets, interface traffic, and UHD software-defined radio configurations.

SCTP & GTP Sockets

Verify that F1 control plane (SCTP on port 38472) and user plane (GTP-U on port 2152) are successfully bound and connected:

ss -nape | grep -Ei 'sctp|38472|2152'

WireGuard Tunnel

In the target Quectel backhaul scenario, verify the WireGuard F1 tunnel after separately proving that the donor DU and access DU are both attached to the shared CU:

wg show wg-quectel-f1

UHD Device Visibility

Verify that the USRP B210 Access Radio is successfully detected on USB 3.0 on serber-minipc:

uhd_find_devices --args "serial=8002816"

Shared B210 Subdevice Probing

To inspect physical subdevice ownership and shared channel tuning on the USRP B210, run the test script:

./scripts/experimental-b210-rf-probe.sh

SIB8/PWS Config Editing

The lab uses System Information Block Type 8 (SIB8) and Public Warning System (PWS) alerts. Modifying the broadcast text involves updating the external OAI configuration and restarting the scenario.

Restart Required

OAI softmodems read the SIB8 config file only during initial startup. Rerunning/applying PWS warnings requires restarting the active gNB/CU/DU process via the TUI.

Procedure to Update Alert Text

  1. Edit the SIB8 configuration file on the target hosts. Typical paths include:
    • Monolithic: /home/serber/monolithic/openairinterface5g/sib8.conf
    • Split Ethernet: /home/serber/cu-du/source/openairinterface5g/sib8.conf
    • Quectel Split: use the pinned external OAI tree documented by the active experiment; do not infer a path from an older launcher
  2. Alternatively, update warnings globally using the TUI menu option "Change PWS/SIB8 warning text everywhere".
  3. Relaunch the scenario from the TUI to broadcast the modified text.
